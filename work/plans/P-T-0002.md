# Plan: LinkSink web MVP — paste to save, organise, filter and search, on phone and desktop

Built on ADR-0002 (OPT-0001 option A, SvelteKit + Better Auth, chosen 2026-10-24).

Sync follows ADR-0001 (own sync, chosen 2026-10-24).

## For the director (plain words)

**What this will do.** Build the first version of LinkSink described in `work/features/F-web-mvp.md` in eleven small
tasks, each built by a builder agent in its own branch, checked automatically, and landed only when the checks pass.
The first task builds a bare app that already runs on your VPS (sign-up, one table, search, the checks, HTTPS),
so every task after it lands on a live app you can open. In parallel, you pick the look: taste-skill deals three
design directions for LinkSink's screens, you choose one, and the screens are built to it. Then come saving, page
details, tags, search and filters, then the full copy on every device with sync (ADR-0001), phone capture, and
export. Each task ends with something you can see. Every table is built ready for sync from the first task, so
adding sync later redoes nothing.

**Choices that are yours.**
1. The stack: OPT-0001 (recommended A).
2. The look: decided, A Ledger (ADR-0003).
3. Decided 2026-10-24: stack A (ADR-0002), own sync (ADR-0001), import yes, fields Source, Media, Tags, Projects, Status, Priority, Archive.
4. The project's automated checks (below): adding them to `bonsai.yaml` is your edit; T-0003 hands you the exact
   lines.

**Facts I need from you before T-0005 deploys (not now):** the VPS's provider, OS and RAM, and a domain or subdomain
pointing at it (HTTPS and the iPhone Shortcut need a real address), SSH access for deploys, a Resend account for the
emails (free), and two storage buckets for backups (any S3-compatible provider; you keep the backup password in your
password manager).

**Risk.** SvelteKit 3 is three weeks old. The auth library says it supports it, but we have not run the two together
yet: T-0003 tests that first and stops with a report if it fails (fallback: SvelteKit 2, or our own auth). Some big sites (Reddit, Instagram,
Medium, Amazon) may refuse to give LinkSink their page details; those links still save, with the address as title.
iPhone cannot add a web app to its share sheet, so iPhone saving goes through a Shortcut until the native app. Sync is
our own code, so its known failure cases (an offline edit lost, a deleted link coming back, a device away for months)
each get a test before it lands. Safari wipes a plain tab's copy after 7 days unused, so LinkSink asks to be added to
the Home Screen.

**Size.** About 13–16 build sessions plus one design session with you, over the eleven tasks. Setup first: a Chromium
browser in this WSL (for taste-skill's screen checks and the browser tests).

## For the builder and verifier

### Parallel-work checkpoint

- **Blocks everything:** T-0003 (skeleton: repo, schema base, auth, ladder). Nothing else starts before it lands.
- **Independent of the app code:** T-0004 (design direction) can run beside T-0003; it produces tokens and static
  mock screens in `design/`, touching no app code.
- **After T-0003, side by side:** T-0005 (deploy) and T-0006 (links + paste) and T-0007 (metadata fetcher, a
  self-contained `src/lib/server/fetch/` module with its own tests). Shared state: T-0006 and T-0007 both touch the
  `links` table; T-0006 owns the schema change, T-0007 adds only the `meta_*` columns in its own migration, landed
  after T-0006.
- **Then in order:** T-0008 (organising, needs T-0006, T-0007 and T-0004's tokens) → T-0009 (search and filters, needs tags) →
  T-0010 (sync and offline; needs every synced table to exist) → T-0011 (PWA install and phone capture; needs sync and
  the deploy) → T-0012 (export/import). T-0013 (a runner measuring first sync and cold start) follows T-0010 and can

- **Shared state:** every task that writes a synced table uses the one versioned write helper from T-0003
  (`src/lib/server/sync/write.ts`); none writes those tables another way (ADR-0001).
- **Smallest safe split:** at most two builders at once, on disjoint folders; migrations land in id order.

4. **T-0006 Links and paste-to-save.** Afterwards: `links` CRUD through `syncWrite`, as a JSON API
   (`POST/GET/PATCH/DELETE /api/links`, cookie or Bearer; DELETE soft-deletes). The client reads and writes only
   through a store interface, `src/lib/store/` (`list`, `get`, `put`, `remove`, `subscribe`), whose first
   implementation talks to the API; T-0010 swaps in the local-first one without touching the screens. `src/lib/url.ts` `normalise(url) → url_key` per the
   one-pager's rule (tracker denylist: `utm_*`, `fbclid`, `gclid`, `dclid`, `msclkid`, `mc_cid`, `mc_eid`, `igshid`,
   `si` on youtu.be/spotify, `ref_src`; keep YouTube `v`/`t`/`list`), unique `(user_id, url_key)`; a duplicate POST
   returns 200 with the existing link and `duplicate: true`. A global `paste` listener (ignored inside text inputs
   other than the paste box) that extracts the first http(s) URL, inserts an optimistic row with a client id
   (`pending`), POSTs, swaps in the server row. Delete with a 5-second undo. List view per T-0004's screens (if
   T-0004 has not landed, plain styles behind the tokens' variable names).
5. **T-0007 Safe metadata fetcher.** Afterwards: `src/lib/server/fetch/safe.ts`, two checks on every request and
   every redirect hop: (a) **before connecting**, if the URL's host is an IP literal (any form the WHATWG URL parser
   normalises: dotted, decimal, hex, octal, bracketed IPv6, IPv4-mapped), check it against the deny ranges directly,
   because Node never calls `lookup` for an IP literal (the verifier showed `http://127.0.0.1` reaching a local
   server past a refuse-all lookup, undici 8.12.3 / Node 22.21.1); (b) for hostnames, an undici `Agent` whose
   `connect.lookup` resolves all addresses and rejects any non-public one, then connects to the validated address.
   Deny ranges: IPv4 private, loopback, link-local incl. 169.254.169.254, CGNAT 100.64/10, 0/8, multicast, reserved;
   IPv6 ::1, ::, fc00::/7, fe80::/10, ff00::/8, and IPv4-mapped/NAT64 forms. `redirect: 'manual'` loop, ≤5 hops, each
   re-checked by (a) and (b); http/https on ports 80/443 only; 8 s total, 1 MB cap, `Accept: text/html`, honest
   `User-Agent: LinkSink/1.0 (+https://<host>)`. `src/lib/server/fetch/meta.ts`: oEmbed for YouTube
   (`youtube.com/oembed`, gives title and thumbnail) and discovered oEmbed links; else stream with htmlparser2 to
   `</head>` for og:*, twitter:*, JSON-LD headline/name, `<title>`, `<meta name=description>`, icons. **X links read
   the x.com page's og tags** (it serves og:title and og:image to the honest User-Agent); X's oEmbed
   (`publish.x.com/oembed`) has no title or image and is used only for the author name and tweet text as a fallback
   description. Charset from the header, then `<meta charset>`, default UTF-8. Images and favicons fetched through
   `safe.ts`, ≤5 MB, decoded with sharp to WebP (preview 320/640 w, favicon 64), stored under
   `data/media/<sha256>.webp`, served by a route with `X-Content-Type-Options: nosniff` and image content types only;
   SVG favicons rasterised, never served raw. Runs in-process after the insert response (a small queue, concurrency
   2, retry once); the client polls `GET /api/links/:id` every second up to 10 s (or until `meta_state` is not
   `pending`). Failure → `meta_state = 'failed'`, title stays the hostname. The fetcher also fills `site_name`,
   `author` (og/JSON-LD author, oEmbed `author_name`), `published_at` (`article:published_time`, JSON-LD
   `datePublished`, YouTube's `uploadDate`), `duration_s` (`og:video:duration`, JSON-LD ISO-8601 `duration`), and the
   page summary into `description`. **Source:** `src/lib/server/classify/source.ts` resolves the final URL's host
   against `sources.hosts` (longest suffix wins; seeded: YouTube = youtube.com, youtu.be, m.youtube.com; GitHub; X =
   x.com, twitter.com; Reddit; Hacker News = news.ycombinator.com; Medium; Substack = *.substack.com; Vimeo; Spotify;
   Wikipedia; arXiv; Stack Overflow; LinkedIn; Instagram), else creates a source named after `og:site_name`, else the
   registrable domain (via `tldts`). **Media:** `src/lib/server/classify/media.ts`, first match wins: (1) URL path
   extension (.pdf → PDF, image extensions → Image, .mp4/.webm → Video, .mp3 → Podcast); (2) host + path rules
   (youtube.com/watch, youtu.be/*, /shorts/, vimeo.com/<id> → Video; github.com/<owner>/<repo> → Repo; x.com/*/status/*,
   reddit.com/r/*/comments/* → Post; open.spotify.com/episode/*, podcasts.apple.com → Podcast; arxiv.org/abs|pdf →
   PDF); (3) response `Content-Type` (application/pdf, image/*, video/*, audio/*); (4) `og:type` (video.* → Video,
   article → Article, music.* → Podcast); (5) oEmbed `type` (video → Video, photo → Image); (6) Page. Each rule has
   a unit test on a recorded fixture. **Never overwrite the person:** a refetch writes `title`, `description`,
   `source_id` or `media` only if that field is not in the link's `user_set` list (below).
6. **T-0008 Organising: tags, projects, status, priority, archive.** Afterwards: `tags`, `projects`, `link_tags`,
   `link_projects` (below); the picker on a link (type to find or create a tag; choose projects; set status and
   priority; change source and media) with keyboard control; a source rename in settings applies to later links from
   its hosts; projects screen (create, rename, colour, description, reorder, delete with confirmation, which removes
   the project from links but keeps the links); tags screen (rename, merge two tags, colour, delete); bulk select in
   the list (`x`, shift-click, long-press on phone) to set tags, projects, status, priority, archive or delete on many
   links in one `syncWrite`; Unsorted view (no tags and no project, not archived); Archive view (`archived_at` set),
   archive and restore with undo; every hand edit of title, description, source or media adds that field to
   `user_set`.
7. **T-0009 Search, filters and keyboard.** Afterwards: on the server, `links_fts` (external content, `unicode61
   remove_diacritics 2`, `prefix='2 3'`, columns title/description/url/notes/tags_text/projects_text, soft-deleted
   rows excluded) kept in sync by triggers, serving `GET /api/links?q=` for the API and the iOS app; `tags_text` and
   `projects_text` columns on links refreshed in the same write that changes a link's tags or projects; one query parser (words AND, prefix on the last word, quoted phrases) shared by server
   and client in `src/lib/search/`. The store interface gains `search(query, filters)`; the API implementation calls
   the server, and T-0010's local one runs the same parser over an in-memory index. Filter state in the URL
   (`?q=&source=<id>,<id>&media=video,article&tags=<id>,<id>&tagmode=any|all&projects=<id>&status=to_read&priority=high&archived=include`),
   any-of within one filter, all-of across filters, `tagmode=all` requiring every picked tag, archived links excluded
   unless `archived=include|only`, in one SQL query with paging (keyset on `created_at,id`, 50 per page); sort by
   saved (default), edited, priority or title. 100 ms debounce, results replace the list without a page load. Keys:
   `/`, `n`, `j/k` and arrows, Enter, `e` edit, `t` tags, `p` projects, `a` archive, `x` select, Ctrl/Cmd+K command
   palette (add, search, jump to a project, tag or source, go to Unsorted/Archive/settings).
8. **T-0010 Sync and offline (ADR-0001).** Afterwards, server: `POST /api/sync/push` takes `{client_id,
   schema_version, mutations: [{id, name, args}]}` (names: `link.put`, `link.remove`, `link.archive`,
   `link.unarchive`, `tag.put`, `tag.remove`, `tag.merge`, `project.put`, `project.remove`, `source.put`,
   `linkTag.add`, `linkTag.remove`, `linkProject.add`, `linkProject.remove`), applies each through
   `syncWrite` in order, skips any `id ≤ sync_clients.last_mutation_id`, rejects a gap, and stores the new last id in
   the same transaction; `GET /api/sync/pull?since=N` returns every synced row with `version > N` (tombstones
   included), in pages of 5,000, plus the new cursor and `tombstone_floor`; `since < tombstone_floor` returns
   `reset: true`; a daily job purges tombstones older than 90 days and raises the floor; an old `schema_version`
   gets 426 and the client reloads. Business rules: a `linkTag.add` or `linkProject.add` naming a deleted link, tag
   or project is dropped (the tombstone wins); an edit to a link deleted on the server is dropped. Client: `src/lib/store/local.ts` on IndexedDB
   (a thin wrapper, no ORM) holding the full copy plus `meta` (cursor, client id, schema version) and an `outbox`;
   every write lands locally and in the outbox at once, then pushes; pulls on start, on focus, on `online`, every
   60 s while visible, and after each push; `reset` → push the outbox, clear, download everything with a progress
   bar. Search over an in-memory index built from the copy (a small library or hand-rolled, chosen by measured size;
   ≤ 10 KB gzipped, loaded after first paint). `navigator.storage.persist()` after the first full sync; a "N changes
   not synced" badge; sign-out (or a 401 after one outbox flush) deletes the IndexedDB database and caches. Settings →
   "Devices": list and revoke sessions (Better Auth `listSessions`/`revokeSession`).

10. **T-0012 Export and import.** Afterwards: `GET /api/export.html` (Netscape bookmark file: one folder per project,

### Data model (SQLite, Drizzle)

- Better Auth's own tables: `user`, `session`, `account`, `verification` (its schema, generated by its CLI).
- **Synced tables** (ADR-0001) each carry `version` integer (the global version of their last write; index
  `(user_id, version)`) and `deleted_at` integer null (tombstone). Ids are ULIDs made on the device, so an offline
  device can create rows. Uniqueness constraints are partial indexes `WHERE deleted_at IS NULL`, so a deleted link can
  be saved again.
- `links`: `id` text (ULID), `user_id` → user; **what it is:** `url` text (as given, trackers removed), `url_key`
  text, `title` text, `description` text, `notes` text; **organising:** `source_id` → sources, `media` text (`video`,
  `article`, `post`, `repo`, `podcast`, `image`, `pdf`, `page`), `status` text null (`to_read`, `in_progress`,
  `done`), `priority` integer null (1 low, 2 medium, 3 high), `archived_at` integer null; **from the page:**
  `site_name`, `author`, `published_at` integer null, `duration_s` integer null, `favicon_path`, `image_path`,
  `meta_state` text (`pending|ok|failed`), `meta_fetched_at` integer null; **bookkeeping:** `user_set` text (JSON
  array of the fields the person set by hand: any of `title`, `description`, `source`, `media`), `saved_via` text
  (`paste`, `share`, `shortcut`, `import`, `api`, `bookmarklet`), `created_at`, `updated_at`, `opened_at` integer null
  (ms), `tags_text`, `projects_text` (search helpers), `version`, `deleted_at`. Unique `(user_id, url_key)` among live
  rows; indexes `(user_id, created_at desc, id)`, `(user_id, archived_at)`, `(user_id, source_id)`.
- `sources`: `id`, `user_id`, `name`, `hosts` text (JSON array of host suffixes), `created_at`, `version`,
  `deleted_at`. Unique `(user_id, name)` among live rows.
- `tags`: `id`, `user_id`, `name` (stored lower-case, trimmed), `color` null, `created_at`, `version`, `deleted_at`.
  Unique `(user_id, name)` among live rows. `tag.merge` moves `link_tags` to the kept tag and soft-deletes the other in
  one write.
- `projects`: `id`, `user_id`, `name`, `color`, `description` null, `position`, `created_at`, `version`,
  `deleted_at`. Unique `(user_id, name)` among live rows. Deleting a project soft-deletes its `link_projects` in the
  same write; the links stay.
- `link_tags`: `link_id` → links, `tag_id` → tags, `user_id`, `created_at`, `version`, `deleted_at`; primary key
  `(link_id, tag_id)`; index `tag_id`. Re-adding a removed tag clears `deleted_at`.
- `link_projects`: as `link_tags`, with `project_id` → projects.
- Status, priority and media are fixed value lists in code (`src/lib/fields.ts`), shared by server, web and later iOS;
  editing those lists is out of scope (F-web-mvp).
- Not synced: `api_tokens` (`id`, `user_id`, `name`, `token_hash`, `scope`, `last_used_at`, `created_at`,
  `revoked_at`); `sync_meta` (`user_id`, `version`, `tombstone_floor`); `sync_clients` (`client_id`, `user_id`,
  `last_mutation_id`, `last_seen_at`).
- Every table carries `user_id` and every query filters on it, so more users later is a sign-up switch, not a
  migration.

### Choices made, and what lost

| Choice | Alternative | Why this one |
|---|---|---|
| better-sqlite3 | node:sqlite | Stable and bundles FTS5; node:sqlite is still a release candidate. Drizzle supports both, so it is a driver swap later |
| Drizzle 0.45 pinned | Drizzle 1.0 RC, Kysely | Stable today; FTS5 written as raw SQL either way |
| argon2id via `@node-rs/argon2` | Better Auth's default scrypt | The Copenhagen Book's first choice; prebuilt binaries, no compiler on the VPS |
| Own SSRF guard: IP-literal check per hop + undici `connect.lookup` | request-filtering-agent | That library is an http.Agent (doesn't plug into fetch/undici) and had two advisories; ours is ~80 lines with tests |
| htmlparser2 streaming to `</head>` | open-graph-scraper, metascraper | Reads only the head, a few small deps; those pull in cheerio (1 MB) |
| unfurl.js | — | Rejected: its repository is archived |
| X metadata from the page's og tags | X oEmbed | X's oEmbed has no title or image; the page serves both to an honest User-Agent |
| Honest User-Agent, no spoofing | Browser or facebookexternalhit UA | Pretending to be another client is bot-check circumvention; a blocked site still saves |
| Local image cache (WebP) | Hotlinking previews | Hotlinks leak views to third parties, break, and can't be sized |
| FTS5 `unicode61` + prefix indexes | trigram tokenizer | ~6× cheaper to build, fast type-ahead; substring search can be added later |
| Polling for metadata | SSE | Ten one-second polls at most per save; no long-lived connections to manage |
| Own sync (ADR-0001) | PowerSync, server-first cache | The person's choice: full offline use with no extra service on the VPS |
| IndexedDB + in-memory search on the web | SQLite in WASM (OPFS) | No extra download, worker or headers, works in every Safari; WASM stays a swap behind the store interface if T-0013's numbers miss |
| Server orders writes, row-level last write wins | Client timestamps, per-field merge, CRDTs | No clock skew; one person rarely edits one link on two devices at once |
| Restic snapshots + Litestream with bucket encryption | Litestream alone | Litestream 0.5 cannot encrypt; restic encrypts on the VPS so the bucket host reads nothing |
| systemd + Caddy | Docker Compose, nginx | Fewest moving parts on one VPS; Caddy does HTTPS by itself |
| Build off the VPS | Build on the VPS | Vite builds can spike memory on a small box |
| iOS Shortcut + token | Web Share Target on iOS | iOS Safari does not support Web Share Target (WebKit bug 194593, open) |

### Risk in the code

- **Better Auth on SvelteKit 3:** declared supported, not yet run by us; if the T-0003 spike fails, stop and report
  blocked with the error; do not patch the library. Fallbacks for the person: SvelteKit 2.x, or option B.
- **better-sqlite3 native build:** pin Node 22 LTS (≥ 22.19) on the VPS (same major as CI); if prebuilds are missing, report
  rather than installing a compiler on the VPS.
- **Metadata from big sites:** never add UA spoofing or headless browsers to get around a block; record the failure
  and move on. A site that needs more is a later decision for the person.
- **Service worker serving stale code:** version-scoped caches keyed on `version` from `$app/env`, old caches
  deleted on activate; a "new version" toast that reloads.
- **Bundle budget:** if rung 5 fails, cut dependencies (no UI kit; icons as inline SVG); do not raise the budget
  without the person.
- **A write that skips `syncWrite`:** other devices never see it. A unit test fails if any synced table changes
  without its `version` rising (a trigger-free check: compare row versions before and after each API test).
- **Sync data loss:** if any sync test shows a lost offline edit or a resurrected delete, the task stops and reports;
  it is never landed with that test skipped or loosened.
- **Three red ladder runs in a row** on the same task: stop and report (the ladder's circuit breaker).
