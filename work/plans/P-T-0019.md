# Plan: import preview, where you see what a file holds and map each folder before anything is saved

## For the director (plain words)

**What this will do.** Choosing a file to import no longer saves anything straight away. It opens a preview:

- how many links the file holds, how many you already have, and how many couldn't be read;
- every folder, with its link count.

**What each folder can become:**

- **a new project:** you can change the name;
- **an existing project:** a project with the same name is picked for you;
- **a tag;**
- **nothing:** its links arrive with no project and land in Unsorted.

The browser's own top folders ("Bookmarks bar", "Other Bookmarks") start on "nothing", and every other folder starts
on "new project".

**Two switches:**

- keep the tags in the file;
- for Pocket files, mark links you'd read as Done.

"Import" saves everything exactly as mapped, and "Cancel" throws it away.

**Choices that are yours.** None left. You asked for this screen, and the defaults above follow what we discussed.
Say if you'd like different defaults.

**Risk.** The server checks the mapping again before saving, so a stale or tampered page can't put links into
someone else's project. The real risk is a file with hundreds of folders becoming a long screen; the folder list
scrolls in its own box. If the preview of a 5,000-link file takes more than a few seconds, the builder reports it
rather than shipping a slow screen.

**Size.** About 3 hours, after T-0012 lands. Then two checks (tests, and the screen in Chrome and Safari's engine),
then you try it with a real export of your bookmarks.

## For the builder and verifier

### Approach

1. **Preview, nothing written.** `previewImport(db, userId, file) → { format, links, duplicates, unreadable,
   folders: [{ path: string[], count, suggested: Mapping }], tags: string[], pocketRead: boolean }`.
   - It reuses T-0012's parsers and the duplicate check by `url_key`, with no writes.
   - The defaults:
     - Top-level browser containers (the `container` check in netscape.ts: Bookmarks bar / Toolbar, Other
       Bookmarks, Bookmarks Menu, Mobile) default to `{ kind: 'none' }`.
     - A path whose joined name equals an existing project's name (case-insensitive) defaults to
       `{ kind: 'existing', projectId }`.
     - Everything else defaults to `{ kind: 'new', name: path.join(' / ') }`.
   - `POST /api/import/preview` (multipart, the same 20 MB limit and body-limit hook as `/api/import`).
2. **Mapping in the writer.** `Mapping = { kind: 'new', name } | { kind: 'existing', projectId } | { kind: 'tag', name }
   | { kind: 'none' }`.
   - `POST /api/import` takes the file plus `mapping: { [pathKey]: Mapping }`, `keepTags`, `pocketReadDone`.
   - The server validates it: every pathKey is in the file, existing ids belong to the user, and names are within the
     length rules. Anything else gets a 400 and nothing is written.
   - New projects are made once per name (two folders mapped to the same new name share one project).
   - It writes through syncWrite in batches of 500, as T-0012 does. With no mapping sent, the defaults apply, so the
     API stays usable without the screen.
3. **The screen,** in `ImportExport.svelte` or a lazily loaded `ImportPreview.svelte`.
   - **Order:** file, then preview, then import or cancel.
   - **Summary:** at the top.
   - **Folder list:** in its own scroll area, max-height 50vh. Each row holds the path, the count and a
     choice-plus-name control. The project picker reuses the store's projects.
   - **Toggles:** keep tags; Pocket read → Done.
   - **The button** reads "Import N links", where N is the links minus the duplicates.
   - **Styling:** ADR-0005's look, using tokens only.
4. **Tests,** listed under "How it gets proved" below.

### Choices made, and what lost

| Choice | Alternative | Why this one |
|---|---|---|
| Stateless: the file is sent twice (preview, then import) | A server-held upload token | No server state or cleanup; files are at most 20 MB and local |
| Defaults computed on the server | On the client | One source, so the no-screen API path gets the same defaults |
| Folder-as-tag is one of the choices | Tags-only toggles | The person asked for "mapping and choosing", and Raindrop users often foldered what are really tags |

### How it gets proved

| Done-when | Proved by |
|---|---|
| Preview writes nothing | An API test: the database snapshot before and after is equal (row counts and versions) |
| Choices and defaults | A unit table over the Chrome, Firefox and Raindrop fixtures, plus an existing-name match |
| Toggles | Unit tests for keepTags and pocketReadDone; e2e for the Pocket switch showing only for Pocket files |
| Import writes the mapping | e2e per choice (new renamed, existing, tag, none → Unsorted), and Cancel |
| Server validation | API tests: foreign project id, unknown path, overlong name, each a 400 with nothing written |
| Look, 200 folders | QA in Chromium and WebKit at 390 and 1440, light and dark, with a generated 200-folder fixture |
| Ladder, size | `bonsai ladder --task T-0019` green; the budget rung |

### Risk in the code

- **Preview speed on 5,000 links:** the duplicate check runs per link. Batch it, as T-0012's writer does.
- **When to stop and report blocked:** the preview takes over 3 s on the 5,000-link fixture, or three red climbs on
  the same rung.
