## What is different now

Pasting a link anywhere on the LinkSink page (not inside the search box or another text field) saves it: the row
appears at once, greyed with "Saving…", and becomes a normal row when the server confirms. Its title is the site's
name (example.com) until T-0007 reads the page. Pasting an address already saved, even with tracking bits, a `www.`,
a `#part` or a trailing slash, makes no copy: the page says "Already saved." and highlights the existing row. Each
row has a Delete button; a deleted link can be brought back with "Undo" for 5 seconds. The box at the top still
takes a typed link and title. Underneath: a JSON API (`/api/links`) that the iPhone Shortcut and scripts can call
with a Bearer token, every write going through `syncWrite`; and the screens now read and write links only through
`src/lib/store/`, so T-0010 can swap in the offline store without touching them.

## Deviations from the plan

1. **Undo is a restore endpoint, not a delayed delete:** DELETE soft-deletes at once and Undo calls `POST
   /api/links/:id/restore` (through syncWrite, version rises; 409 if the same address was saved again meanwhile). The
   store gains `restore(id)` beside the five named methods. Reason: a delete that waits 5 s in the browser is lost
   if the tab closes. T-0010 needs a `link.restore` mutation for this (its list has none) — proposed below.
2. **Clients outside the browser must send `Content-Type: application/json` on every write**, a body-less DELETE
   and restore included: SvelteKit 3.1 refuses a write with no content type and no matching Origin as a cross-site
   form post (log 10:11). The API also refuses non-JSON bodies with 415 (a cross-site form or `text/plain` post).
   T-0011's Shortcut steps must set the header.
3. **No `sources` table yet:** PATCH accepts any `sourceId` text up to 64 characters (no foreign key) and marks
   `source` in `user_set`. The plan's step 4 does not name `sources`; T-0007 (source classifier) or T-0008 adds it.
   No migration in this task, so T-0007 keeps its numbering.
4. **`user_set` grows only on a real change:** a PATCH that sends the current value of a field neither writes nor
   marks it (the brief says "changes"). A typed title on create counts as the person's (`user_set: ["title"]`).
5. ~~The scheme stays in `url_key`~~ — superseded in the fix round: the person decided (2026-10-24) that `http://`
   and `https://` of one address are one link; `url_key` now leaves the scheme out.
